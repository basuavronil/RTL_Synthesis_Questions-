### FAQ: Can one variable be driven from two always blocks?

**No.** In Verilog and SystemVerilog, a variable declared as a `reg` or logic type cannot be driven by multiple procedural blocks (such as two separate `always` blocks) concurrently.

#### 1. Why Is It Bad?
* **Multiple Driver Conflict:** If two `always` blocks attempt to assign values to the same variable at the same time, the hardware simulator and synthesis tool cannot determine which driver takes precedence, resulting in conflicting assignments.

#### 2. Synthesis and Simulation Behavior
* **Synthesis Errors:** Modern synthesis tools will throw a fatal error (e.g., *`Multiple drivers for net...`* or *`LHS has multiple drivers`*) and abort compilation because standard registers cannot be wired to multiple output sources.
* **Simulation Contention (`x` State):** In simulation, competing procedural drivers writing to the exact same variable simultaneously will cause driver contention, usually resulting in an unknown (`x`) state propagating through your simulation waveform.

> **Exception:** If you need multiple sources to drive a single wire, use a net data type like `wire` driven by continuous assignments (`assign`) or tristate logic (`tri`), rather than procedural `reg`/`logic` variables.
