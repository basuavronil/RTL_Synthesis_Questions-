# Verilog RTL Design & Synthesis FAQ

## FAQ: Inferred Latches

### Is a latch a synthesis error? 
**No, only a warning.** It is legal hardware, but usually unintended.

---

## Understanding Inferred Latches in Combinational Logic

### 1. Why is it not a Synthesis Error?
* Standard cell libraries in both FPGAs and ASICs contain physical latch primitives (level-sensitive memory elements).
* Because Verilog code with an incomplete conditional statement can technically map to a real physical latch cell, the code compiles successfully without failing.

### 2. Why is it flagged as a Warning?
* **Level-Sensitive Nature:** Modern synchronous design relies on edge-triggered flip-flops. Latches pass data straight through while their enable signal is high, making them prone to glitches.
* **Unintended Memory:** Omitting an `else` branch or a default assignment forces the synthesis tool to create a memory cell to "remember" the previous state, which is almost always an accidental design bug rather than an intentional choice.

---

## How to Prevent Inferred Latches

To ensure your combinational `always @(*)` blocks do not infer latches (and avoid any synthesis warnings), assign a **default value** at the very beginning of the block:

```verilog
always @(*) begin
    // Provide a default value to ensure complete coverage across all paths
    out = 1'b0; 

    if (sel) begin
        out = data_in;
    end
end
