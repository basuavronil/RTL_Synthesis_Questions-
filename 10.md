### Q: How do blocking assignments (`=`) behave differently in sequential blocks when chaining variables (`a = b; b = c; c = a;`) versus propagating a constant (`a = 1; b = a; c = b;`)?

**A:** Because blocking assignments execute instantly and sequentially line-by-line within a clock edge, the cyclic pattern corrupts data flow and breaks synthesis, whereas the constant pattern cascades a hardcoded value across registers.

#### Side-by-Side Comparison

| Feature / Aspect | Cyclic Shift Pattern (`a = b; b = c; c = a;`) | Constant Propagation Pattern (`a = 1; b = a; c = b;`) |
| :--- | :--- | :--- |
| **Data Propagation** | Values overwrite sequentially; `c` ends up copying `b` instead of rotating the original value of `a`. | Values overwrite sequentially; **all** registers (`a`, `b`, and `c`) capture the hardcoded constant `1`. |
| **Simulation Behavior** | Evaluates instantly line-by-line; data path is corrupted, failing to rotate values properly. | Evaluates instantly line-by-line; `a` becomes `1`, `b` immediately reads `1`, and `c` immediately reads `1`. |
| **Synthesis Behavior** | Fails to map to clean registers; generates unintended **combinational feedback loops** or latches. | Synthesizes **3 distinct flip-flops**, but optimizes their data (`D`) inputs to tie directly to a constant `1` source. |
| **Flip-Flops Formed** | Ambiguous/Broken logic (fails to form a valid register chain). | **3 Flip-Flops**, acting as constant drivers rather than an active shift pipeline. |

#### Why It Happens
1. **Immediate Overwriting:** Blocking assignments (`=`) update variables instantly at the exact line they are written. 
2. **Cyclic Failure:** In the first case, `c = a` reads the *already-modified* `a` from the first line, destroying the intended rotation.
3. **Constant Cascading:** In the second case, setting `a = 1` forces every subsequent line in that clock edge to immediately read and pass that same `1` down the chain.

#### Summary Rule
* Chaining state variables with blocking assignments (`=`) in a sequential block causes unintended immediate overwriting. Use **non-blocking assignments (`<=`)** for proper shift registers and state propagation.
