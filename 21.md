### FAQ: Why is a combinational loop bad, and how do tools handle it?

A **combinational loop** occurs when the output of a combinational logic gate is fed back into its own input (directly or through other combinational gates) without any sequential element (flip-flop or latch) breaking the path. 

#### 1. Why Is It Bad?
* **Oscillation and Instability:** Without a clock edge to control state changes, a loop acts like a ring oscillator. Signals can flip infinitely at the maximum physical speed of the gates, destroying power integrity and causing unpredictable logic states.
* **Non-Deterministic Race Conditions:** The final state depends entirely on microscopic differences in gate propagation delays rather than synchronous control.
* **Breaks Static Timing Analysis (STA):** STA relies on Directed Acyclic Graphs (DAGs) with clear starting (registers/ports) and ending points. A loop creates a cycle, making it mathematically impossible for synthesis tools to calculate setup and hold times.

---

### How Simulation vs. Synthesis Behaves

#### 🔬 Simulation Behavior
* **Zero-Delay Hangs:** In event-driven simulators, a combinational loop with no delay can cause a **zero-delay infinite loop**, freezing your simulation or crashing the simulator process as it gets stuck in an infinite delta-cycle evaluation.
* **`x` Propagation:** If the loop resolves to contradictory states, the simulator may propagate unknown (`x`) values through the rest of your design.

#### 🛠️ Synthesis Behavior
* **Tool Warnings & Errors:** Modern synthesis tools (like Vivado or Design Compiler) will immediately flag combinational loops with critical errors or warnings.
* **Arbitrary Loop Breaking:** To finish mapping the netlist, the tool will often attempt to "break" the loop by arbitrarily cutting a wire, inserting a latch, or mapping it in a non-deterministic way—resulting in hardware that completely diverges from your intent.

### Code Example: The Combinational Loop Anti-Pattern

#### ❌ Dangerous Combinational Loop
```verilog
module bad_combinational_loop (
    input  en,
    input  data_in,
    output out_signal
);

    // BAD: The output feeds back into its own combinational expression!
    // There is no register (flip-flop) between out_signal and the logic inside.
    assign out_signal = en ? (data_in | out_signal) : 1'b0;

endmodule
```
## Correct Code 
```verilog
module clean_sequential_logic (
    input      clk,
    input      rst_n,
    input      en,
    input      data_in,
    output reg out_signal
);

    // GOOD: State is safely captured and updated on a clock edge.
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            out_signal <= 1'b0;
        end else if (en) begin
            out_signal <= data_in | out_signal; // Safe sequential feedback
        end
    end

endmodule
```
