### Q: When is a blocking assignment (`=`) acceptable inside a sequential (`always @(posedge clk)`) block, and how does the `temp = a; a <= b; b <= temp;` pattern behave?

**A:** Blocking assignments are acceptable **only for temporary local variables** that are fully computed and consumed within the *same* clock cycle. The specific pattern `temp = a; a <= b; b <= temp;` is a classic example of this, safely executing a single-cycle register swap.

#### Simulation vs. Synthesis Behavior
* **Simulation:** Executes correctly. The blocking assignment (`temp = a`) captures `a` instantly before any updates happen. The subsequent non-blocking assignments (`<=`) use these values to schedule the register swap cleanly at the end of the time step.
* **Synthesis:** Synthesizes successfully. Tools treat the temporary variable (`temp`) as internal combinational logic/routing and map `a` and `b` to flip-flops with multiplexers that perform the swap on the rising clock edge.

#### Detailed Explanation of the Swap Pattern
1. **`temp = a;` (Blocking):** 
   * Evaluates and updates `temp` **immediately** at the start of the block, capturing the current value of `a` before it changes.
2. **`a <= b;` (Non-Blocking):** 
   * Schedules `a` to receive the value of `b` at the end of the clock cycle.
3. **`b <= temp;` (Non-Blocking):** 
   * Schedules `b` to receive the original value of `a` (held safely in `temp`) at the end of the clock cycle.

#### Best Practices & Rules to Follow
* **Single-Scope Lifetime:** The temporary variable (`temp`) must be written to and fully read *within the same block and clock cycle*. Never read it across clock boundaries.
* **No Cross-Block Sharing:** Do not use blocking assignments to pass state between separate `always` blocks.
* **Use Non-Blocking for State:** Always use non-blocking assignments (`<=`) for the actual registers (`a` and `b`) that store state across clock edges.
