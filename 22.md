### FAQ: What is a glitch, and can synthesis remove it?

A **glitch** is a brief, unintended transition (a voltage spike or false pulse) on a digital signal caused by unequal propagation delays through different combinational logic paths (timing hazards).

#### 1. Can Synthesis Remove It?
**No.** Synthesis tools optimize for area, timing, and power using static timing analysis (STA). They map RTL to standard cells, but they **do not guarantee glitch-free logic**. Combinational gates have varying physical delays, meaning two signals changing at slightly different times can cause the output to flicker before settling.

#### 2. Why You Must Never Drive Clocks or Resets from Combinational Logic
* **Clocks:** A glitch on a clock line acts as an extra, unintended clock edge, immediately corrupting flip-flop states and causing unpredictable hardware failures in silicon.
* **Resets:** A glitch on an asynchronous reset line can inadvertently trigger a partial reset or put registers into invalid states.

### Code Examples: Glitchy Combinational Clock vs. Clean Design

#### ❌ The Dangerous Anti-Pattern (Bad Verilog)
Never use combinational logic (such as an XOR or gate network) to generate a clock. Microscopic differences in physical gate and wire delays will cause glitches that act as phantom clock edges in real hardware.

```verilog
module glitchy_clock_example (
    input  signal_a,
    input  signal_b,
    input  data_in,
    output reg q_out
);

    // BAD: Combinational logic driving a clock signal!
    // Propagation delays between signal_a and signal_b will cause glitches.
    wire clk_bad = signal_a ^ signal_b;

    // BAD: Using a combinational output as a clock
    always @(posedge clk_bad) begin
        q_out <= data_in; // Triggers unpredictably due to glitches!
    end

endmodule
```
## Correct Code 
```Verilog
module clean_design (
    input      clk,      // Clean, dedicated global clock
    input      rst_n,    // Synchronized active-low reset
    input      data_in,
    output reg q_out
);

    // GOOD: Data is processed sequentially, clock is strictly a global net.
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            q_out <= 1'b0;
        end else begin
            q_out <= data_in; // Clean, glitch-free sampling
        end
    end

endmodule
```
