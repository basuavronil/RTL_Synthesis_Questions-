# What is inferred if an always block is sensitive to `posedge clk` and `negedge rst_n`?

**Answer:** A flip-flop with an **asynchronous active-low reset**.

## Example

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 1'b0;   // reset takes effect immediately
    else
        q <= d;      // normal operation on clock edge
end
```

## Why this is inferred

- **`posedge clk`** makes the block edge-triggered, so a flop is inferred.
- **`negedge rst_n`** in the sensitivity list means the block also triggers when reset falls, **independent of the clock**. That makes the reset *asynchronous*.
- **`if (!rst_n)`** checks for a low level, so the reset is *active-low* (reset is asserted when `rst_n = 0`).

## Behavior

| `rst_n` | `clk` | Result |
|---|---|---|
| Falls to 0 | Any | `q` is cleared immediately |
| 0 | Any | `q` held at 0 |
| 1 | Rising edge | `q` captures `d` |

## Synchronous vs. asynchronous reset

| Style | Sensitivity list | Reset acts |
|---|---|---|
| Asynchronous | `posedge clk or negedge rst_n` | Immediately, without waiting for the clock |
| Synchronous | `posedge clk` | Only on a clock edge |

## Key points

- The reset condition inside the block must match the edge: `negedge rst_n` pairs with `if (!rst_n)`.
- Use `posedge rst` with `if (rst)` for an active-high asynchronous reset.
- Synthesis maps this to a flop with an async reset pin (e.g., a DFF with `RN`/`CLR`).
