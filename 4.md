# 4.	What does q1=d; q2=q1; q3=q2; synthesize to in a clocked block? 
# Blocking vs Non-Blocking Assignments in Verilog

A short, practical demo of why assignment style inside a clocked `always` block decides whether you get a **shift register** or **three parallel flip-flops**.

## The Problem

```verilog
always @(posedge clk) begin
    q1 = d;
    q2 = q1;
    q3 = q2;
end
```

This looks like a 3-stage shift register, but it is not.

## Why It Fails

### 1. Simulation view

Blocking assignments (`=`) execute sequentially and update immediately within the same clock edge:

1. `q1 = d;` : `q1` takes the value of `d`
2. `q2 = q1;` : `q2` takes the just-updated `q1` (which is `d`)
3. `q3 = q2;` : `q3` takes the just-updated `q2` (also `d`)

All three variables hold `d` at the same time.

### 2. Synthesis view

The synthesis tool derives the D-input of each flip-flop:

| Flip-flop | Next-state equation |
|-----------|---------------------|
| `q1` | `d` |
| `q2` | `q1 = d` |
| `q3` | `q2 = d` |

The chain collapses, and the D-inputs of `q1`, `q2` and `q3` are all tied directly to `d`. The result is three parallel flip-flops that load `d` simultaneously (the tool may even merge them into one).

## The Fix: Non-Blocking Assignments

```verilog
always @(posedge clk) begin
    q1 <= d;    // q1 gets d
    q2 <= q1;   // q2 gets the OLD value of q1
    q3 <= q2;   // q3 gets the OLD value of q2
end
```

Non-blocking assignments (`<=`) evaluate all right-hand sides using the **old** values, then update the left-hand sides at the end of the time step. This preserves the one-cycle delay between stages and creates a genuine 3-stage shift register.

## Summary

| Assignment | Inside a clocked `always` block | Hardware result |
|------------|----------------------------------|-----------------|
| Blocking (`=`) | Evaluates sequentially, values propagate instantly | Parallel registers (chain collapses) |
| Non-blocking (`<=`) | Updates scheduled for end of time step | Pipeline / shift register |

## Rule of Thumb

- Use `<=` for **sequential** (clocked) logic
- Use `=` for **combinational** logic
- Do not mix both styles in the same `always` block

## Try It Yourself

Minimal testbench to see the difference in simulation:

```verilog
module tb;
    reg clk = 0, d = 0;
    wire q1_nb, q2_nb, q3_nb;
    wire q1_b,  q2_b,  q3_b;

    shift_nonblocking u_nb (.clk(clk), .d(d), .q1(q1_nb), .q2(q2_nb), .q3(q3_nb));
    shift_blocking    u_b  (.clk(clk), .d(d), .q1(q1_b),  .q2(q2_b),  .q3(q3_b));

    always #5 clk = ~clk;

    initial begin
        $monitor("t=%0t d=%b | NB: %b%b%b | B: %b%b%b",
                 $time, d, q1_nb, q2_nb, q3_nb, q1_b, q2_b, q3_b);
        #12 d = 1;
        #10 d = 0;
        #30 $finish;
    end
endmodule
```

Expected behavior: the non-blocking version delays `d` by one clock per stage, while the blocking version shows `d` on all three outputs at once.

## 📌 Key Takeaways: Simulation Mechanics & Scheduler Regions

To truly understand why blocking and non-blocking assignments behave differently in hardware, we have to look at how the Verilog event scheduler handles them:

### 1. Blocking Assignments (`=`)
* **Simulation Region:** Evaluated and updated entirely in the **Active region** sequentially.
* **Mechanism:** Because values propagate instantly line-by-line, `q1`, `q2`, and `q3` all end up holding `d` within the same delta cycle. 
* **Synthesis Result:** The synthesizer sees three registers being fed directly by `d`, resulting in **three parallel flip-flops** rather than a shift register.

### 2. Non-Blocking Assignments (`<=`)
* **Simulation Region:** RHS expressions are evaluated using current values in the **Active region**, but the actual assignments to LHS variables are scheduled and deferred to the **NBA (Non-Blocking Assignment) region**.
* **Mechanism:** `q1` gets `d`, while `q2` and `q3` capture the *old* pre-clock-edge values of their respective right-hand sides. 
* **Synthesis Result:** This preserves the temporal delay across clock edges, correctly inferring a **true 3-stage shift register / pipeline**.

> **Pro Tip:** Mastering how Verilog bridges top-to-bottom software simulation behavior with parallel hardware reality via the Active and NBA regions is essential for writing clean, bug-free RTL.
