# 54. What is a setup time violation and how do you fix it at RTL?

## Answer

A **setup time violation** occurs when data arrives **too late** at a flip-flop's input. The data must be stable for a minimum time (the *setup time*) **before** the active clock edge. If it isn't, the flop may capture the wrong value or go metastable.

## Condition

```
T_clk-to-q + T_comb(max) + T_setup <= T_clk - T_skew
```

A violation happens when the combinational path delay is too long for the clock period.

## How to Fix at RTL

| Technique | Description |
|-----------|-------------|
| **Pipelining** | Break a long combinational path into stages by inserting registers, so each stage has less logic delay. |
| **Retiming** | Move registers across combinational logic to balance delays between stages. |
| **Simplify logic** | Reduce logic depth: restructure expressions, use parallel prefix/tree structures, remove redundant logic, and avoid long priority chains. |

## Additional Tips

- Replace deep `if/else` chains with parallel `case` logic.
- Use resource sharing carefully; it can lengthen paths.
- Duplicate registers for high-fanout signals.
- As a last resort, relax the clock frequency (increase the period).
