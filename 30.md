# 2 state vs 3 State FSM
# RTL Design Patterns: 2-Block vs. 3-Block FSM Architectures

A reference guide and comparison for implementing robust, synthesis-friendly Finite State Machines (FSMs) in Verilog and SystemVerilog.

---

## Overview

Choosing the right procedural block structure is critical for writing predictable RTL. A well-structured FSM eliminates unintended latches, simplifies static timing analysis (STA), and ensures clean waveform debugging in simulation tools (like Questa, VCS, or GTKWave). 

Here is a breakdown of the two industry-standard multi-block FSM coding styles.

---

## 1. 2-Block FSM Style

> **Separates the state register (sequential) from a combined next-state and output logic block (combinational).** 

This is a popular design compromise that keeps code concise while retaining all safety benefits against latches.

### Structure
1. **Block 1 (`always` / `always_ff`):** Sequential state register (`current_state <= next_state`).
2. **Block 2 (`always @(*)` / `always_comb`):** Combined evaluation of both the next-state logic and the output logic.

### Pros & Cons
* **Pros:** Concise and compact; reduces the number of procedural blocks to manage; easy to write for simpler Moore or Mealy machines.
* **Cons:** As FSM complexity grows, combining output decoding and next-state logic into a single block can make the code harder to maintain.

---

## 2. 3-Block FSM Style

> **Completely isolates the state register, next-state logic, and output logic into three separate blocks.** 

While slightly more verbose, it provides the cleanest organizational structure—especially for complex Mealy machines where output decoding can otherwise become messy.

### Structure
1. **Block 1 (`always` / `always_ff`):** Sequential state register (`current_state <= next_state`).
2. **Block 2 (`always @(*)` / `always_comb`):** Pure combinational next-state evaluation.
3. **Block 3 (`always @(*)` / `always_comb`):** Pure combinational output logic (or registered outputs, depending on design specs).

### Pros & Cons
* **Pros:** Ultimate modularity and readability; cleanly separates data/control output decoding from state transition logic; highly recommended for large-scale production IPs and complex Mealy FSMs.
* **Cons:** Requires writing slightly more lines of code due to the extra procedural block.

---

## Quick Comparison

| Feature | 2-Block FSM | 3-Block FSM |
| :--- | :--- | :--- |
| **Sequential Blocks** | 1 (`always_ff`) | 1 (`always_ff`) |
| **Combinational Blocks** | 1 (Next-State + Outputs) | 2 (Next-State & Outputs separated) |
| **Code Verbosity** | Concise | Moderate / Verbose |
| **Best Suited For** | Standard controllers, simple Moore/Mealy FSMs | Complex Mealy machines, large-scale industrial RTL |
| **Latch Protection** | High (with proper default assignments) | Maximum (isolated output blocks) |
