# Hardware Synthesis Guide: For Loops in Verilog

A critical concept in Hardware Description Languages (HDLs) is understanding how procedural loops differ from software loops. In hardware design, **`for` loops are synthesizable only when their bounds are static and known at compile-time.**

Unlike software engines that execute loop iterations sequentially over time, HDL synthesizers treat combinatorial `for` loops as **hardware generators**. The synthesis tool **unrolls** the loop, duplicating physical logic gates for each iteration in parallel.

---

## Key Synthesis Rules

| Feature | Synthesizable? | Hardware Behavior | 
| :--- | :--- | :--- | 
| **Static Bounds** (`i < 8`) | ✅ Yes | Unrolls into fixed parallel hardware logic gates. | 
| **Constant Bounds** (`i < MAX_VAL`) | ✅ Yes | Unrolls based on compile-time constants or macros. | 
| **Dynamic/Runtime Bounds** (`i < input_var`) | ❌ No | Cannot allocate variable physical silicon dynamically. | 

---

## 1. Synthesizable Example: Static Bounds

In this example, the loop bounds (`0` to `8`) are fixed constants known at compile time. The synthesis tool cleanly unrolls this loop into parallel combinational adders.

```verilog
// Module: Population Count (Bit Counter)
// Purpose: Counts the number of active high bits in an 8-bit input vector.

module bit_counter (
    input  [7:0] data_in,
    output reg [3:0] count_out
);

    integer i;

    always @(*) begin
        count_out = 4'd0;
        
        // SYNTHESIZABLE: Bounds (0 to 8) are static constants.
        // The synthesis tool unrolls this into parallel addition stages.
        for (i = 0; i < 8; i = i + 1) begin
            if (data_in[i]) begin
                count_out = count_out + 1'b1;
            end
        end
    end

endmodule
```

---

## 2. Unsynthesizable Example: Dynamic Bounds

In this example, the loop condition relies on an input signal (`limit`) that changes dynamically at runtime. Synthesis engines (like Vivado, Quartus, or Yosys) will throw an error because physical silicon cannot dynamically expand or shrink its combinational logic gates at runtime.

```verilog
// Module: Dynamic Mask Generator (INVALID SYNTHESIS)
// Purpose: Attempts to copy bits up to a dynamic input boundary.

module dynamic_loop_error (
    input  [3:0] limit,     // Runtime variable input
    input  [7:0] data_in,
    output reg [7:0] data_out
);

    integer i;

    always @(*) begin
        data_out = 8'd0;
        
        // UNSYNTHESIZABLE: 'limit' is an input signal, not a constant.
        // Synthesis Error: Loop condition must evaluate to a compile-time constant.
        for (i = 0; i < limit; i = i + 1) begin
            data_out[i] = data_in[i];
        end
    end

endmodule
```

## 3. Recommended Solution for Variable Iterations

If an operation must process variable counts at runtime, you must convert the spatial loop into a **temporal sequence** (using a clock and registers) that evaluates over multiple clock cycles:

```verilog
// Module: Sequential Dynamic Mask
// Purpose: Correctly handles dynamic counts over multiple clock cycles.

module dynamic_mask_sequential (
    input        clk,
    input        rst_n,
    input        start,
    input  [3:0] limit,
    input  [7:0] data_in,
    output reg [7:0] data_out,
    output reg       done
);

    reg [3:0] counter;

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            counter  <= 4'd0;
            data_out <= 8'd0;
            done     <= 1'b0;
        end else if (start) begin
            counter  <= 4'd0;
            data_out <= 8'd0;
            done     <= 1'b0;
        end else if (counter < limit) begin
            data_out[counter] <= data_in[counter];
            counter           <= counter + 1'b1;
        end else begin
            done <= 1'b1;
        end
    end

endmodule
```
