# Is `while` synthesizable?

**Answer:** Only if it has a static bound, and it is generally avoided.

## Key idea

Like a `for` loop, a synthesizable `while` loop is **unrolled at synthesis time** into replicated logic. For that to work, the tool must be able to determine the **number of iterations at compile time**. If the loop condition depends on a runtime signal, the tool cannot know how many copies of hardware to build, so the loop is not synthesizable.

## Synthesizable example (static bound)

```verilog
always @(*) begin
    i = 0;
    while (i < 4) begin
        y[i] = a[i] & b[i];
        i = i + 1;
    end
end
```

The condition depends only on constants and the loop counter, so the tool can unroll it into **four AND gates**, the same as a `for` loop.

## Non-synthesizable example (dynamic bound)

```verilog
always @(*) begin
    while (count < data_in) begin   // data_in is a runtime signal
        count = count + 1;
    end
end
```

Here the number of iterations depends on `data_in`, which changes during operation. Hardware cannot grow or shrink at runtime, so synthesis tools report an error or an unbounded loop warning.

## Why it is generally avoided

- **Readability:** A `for` loop shows the bounds in one line, while a `while` loop hides them in the condition and body.
- **Risk of infinite loops:** A forgotten increment can hang the tool or simulation.
- **Tool support varies:** Some synthesis tools reject `while` loops or limit the unroll depth.
- **No advantage:** Any synthesizable `while` loop can be rewritten as a `for` loop, which is clearer.

## `for` vs. `while` in RTL

| Aspect | `for` loop | `while` loop |
|---|---|---|
| Bound visibility | Explicit in the header | Hidden in the condition |
| Synthesizable | Yes, with constant bounds | Only with a static bound |
| Common in RTL | Yes | Rare |
| Typical use | Hardware replication | Mostly testbenches |

## Where `while` is fine

- **Testbenches and simulation:** For example, waiting until a condition is met (`while (!done) #10;`). This code is never synthesized.
- **Behavioral models** that are not meant for synthesis.

## Better alternatives for runtime-dependent behavior

If you need something to repeat a variable number of times in real hardware, use:

- A **counter** that increments each clock cycle
- A **finite state machine (FSM)** that loops through states until a condition is met

This spreads the work over multiple clock cycles instead of trying to build it as combinational logic.

## Summary

`while` is synthesizable only when its iteration count is fixed at compile time, in which case it unrolls like a `for` loop. In practice, use `for` for synthesizable code and keep `while` for testbenches.
