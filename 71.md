# Is `generate` synthesizable?  

**Answer:** Yes, it is elaborated at compile time.  

## Key idea  

A `generate` block is not hardware that runs. It is an **instruction to the tool** that creates hardware structure during **elaboration**, before synthesis maps anything to gates. By the time synthesis begins, the `generate` construct has already been expanded into ordinary module instances, gates, and `assign` or `always` blocks.

## Requirement

All conditions and loop bounds must be **constant expressions** known at elaboration time, such as `parameter`, `localparam`, or `genvar` values. They cannot depend on runtime signals.

## Types of generate constructs

### 1. Generate `for` loop

Creates repeated copies of hardware.

```verilog
genvar i;
generate
    for (i = 0; i < 8; i = i + 1) begin : gen_and
        assign y[i] = a[i] & b[i];
    end
endgenerate
```

This produces **eight AND gates**, each in its own named scope (`gen_and[0]` to `gen_and[7]`).

### 2. Generate `if`

Includes or excludes hardware based on a parameter.

```verilog
generate
    if (USE_FAST_ADDER) begin : gen_fast
        fast_adder u_add (.a(a), .b(b), .sum(sum));
    end else begin : gen_slow
        slow_adder u_add (.a(a), .b(b), .sum(sum));
    end
endgenerate
```

Only one branch is built. The other does not exist in the final design.

### 3. Generate `case`

Selects one of several structures based on a parameter.

```verilog
generate
    case (WIDTH)
        8:  byte_unit  u_unit (.d(d), .q(q));
        16: half_unit  u_unit (.d(d), .q(q));
        default: word_unit u_unit (.d(d), .q(q));
    endcase
endgenerate
```

## `generate` vs. procedural `for`

| Aspect | `generate for` | Procedural `for` (inside `always`) |
|---|---|---|
| Where used | Module level | Inside a procedural block |
| Can create | Instances, `assign`, `always` blocks, wires | Only repeated statements |
| Loop variable | `genvar` | `integer` or `reg` |
| Evaluated | At elaboration | At synthesis (unrolled) |

## Common uses

- Instantiating arrays of modules (e.g., a bank of registers or processing elements)
- Parameterized, reusable designs (width and feature selection)
- Optional features turned on or off with a parameter
- Building structures like adder trees or bit-slice logic

## Things to watch out for

- **Bounds must be constant.** A loop limit that depends on an input signal will fail.
- **Name each block** (e.g., `begin : gen_and`) so hierarchy names are clear for debugging and constraints.
- **Area grows with iteration count**, since each iteration creates real hardware.
- `genvar` exists only at elaboration. It is not a real signal and cannot be assigned at runtime.

## Summary

`generate` is fully synthesizable because it is resolved at **compile (elaboration) time**. It is the standard way to write parameterized, repeated, or optional hardware, as long as every condition and bound is a constant.
