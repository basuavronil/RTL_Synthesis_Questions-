# Verilog & SystemVerilog RTL Design FAQ

## FAQ: Fully Covered Case Statements Without Defaults

### Does a case with all combinations covered but no default infer a latch? 
**Not if it is truly full** (e.g., a 2-bit select with all 4 cases explicitly written), **but X/Z values in simulation can mislead, so always add a default.**

---

## Understanding Full Case Statements and X/Z Hazards

### 1. Synthesis Perspective (No Latch)
If every possible binary combination of your selection signal is explicitly covered (for instance, all 4 permutations for a 2-bit bus), the synthesis tool recognizes a fully specified truth table. It builds pure combinational logic and **will not** infer a latch.

### 2. Simulation Perspective (X/Z Hazards)
* **Unknown Propagation:** During reset sequences or uninitialized startup phases, simulation signals frequently evaluate to `X` (unknown) or `Z` (high impedance).
* **Matching Failure:** If the selector contains an `X` or `Z`, none of the explicit literal cases will match. Without a `default` statement, the simulator will not execute an assignment, leading to unpredictable simulation results or severe mismatches between pre-synthesis simulation and actual hardware.

---

## Recommended Practice

Always include a `default` clause to handle uninitialized simulation states and guarantee robust behavior across both simulation and synthesis tools:

```verilog
always @(*) begin
    case (sel)
        2'b00:    out = data_0;
        2'b01:    out = data_1;
        2'b10:    out = data_2;
        2'b11:    out = data_3;
        default:  out = 1'b0; // Safely catches X/Z simulation states
    endcase
end
