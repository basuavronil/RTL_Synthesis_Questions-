### Verilog Scheduling Region Order: Simulation vs. Synthesis

#### **1. Simulation: Stratified Event Queue**
Verilog is a discrete-event simulation language. Within a single time step, events execute in a strict priority order:
1. **Active Region:** Blocking assignments (`=`), continuous assignments (`assign`), and RHS evaluation of non-blocking assignments.
2. **Inactive Region:** Zero-delay (`#0`) events (avoid in RTL).
3. **NBA (Non-Blocking Assignment) Region:** Updates for non-blocking assignments (`<=`).

* **Why NBA Avoids Races:** By separating RHS evaluation (Active) from LHS updating (NBA), all concurrent blocks read the *old* values first before any variables update. This mimics simultaneous physical flip-flop triggering.

#### **2. Synthesis Reality**
* **Hardware Mapping:** Synthesis tools ignore simulation scheduling regions, delta cycles, and `#0` delays. They translate code semantic intent into physical gates.
* **Coding Rule:** Use **non-blocking (`<=`)** for sequential logic (maps to registers/flip-flops) and **blocking (`=`)** for combinational logic. Mixing them in sequential blocks causes simulation-synthesis mismatches and infers unintended latches.
