## Verilog Case Statement Comparison: `case`, `casez`, and `casex`

### 1. Standard `case` (Strict Exact Match with `?`)
In standard `case`, **`?` is not a wildcard**. It is treated literally as a `z` (high-impedance) value, and strict bit-by-bit identity is required.

| Incoming Data | Case Branch Value | Does it Match? | Why? |
| :--- | :--- | :--- | :--- |
| **`0` or `1`** | **`?` (treated as `z`)** | **No** | Strict match required; a known value (`0` or `1`) does not match a `z`/`?`. |
| **`z`** | **`?` (treated as `z`)** | **Yes** | Exact bit match (`z` matches `z`). |
| **`x`** | **`?` (treated as `z`)** | **No** | Strict match required; an `x` does not match a `z`. |
| **`0`** | **`0`** | **Yes** | Exact bit match. |
| **`1`** | **`1`** | **Yes** | Exact bit match. |
| **`x`** | **`x`** | **Yes** | Exact bit match. |
| **`z`** | **`z`** | **Yes** | Exact bit match. |

---

### 2. `casez` (`?` and `z` as Wildcards in Case Branches Only)
In `casez`, **`?` (and `z`) written in the case statement branches act as universal wildcards**, matching anything coming in. Incoming data values themselves cannot act as wildcards.

| Incoming Data | Case Branch Value | Does it Match? | Why? |
| :--- | :--- | :--- | :--- |
| **`0`** | **`?` (or `z`)** | **Yes** | The `?` in the branch acts as a wildcard, matching the incoming `0`. |
| **`1`** | **`?` (or `z`)** | **Yes** | The `?` in the branch acts as a wildcard, matching the incoming `1`. |
| **`x`** | **`?` (or `z`)** | **Yes** | The `?` in the branch acts as a wildcard, matching the incoming `x`. |
| **`z`** | **`?` (or `z`)** | **Yes** | The `?` in the branch acts as a wildcard, matching the incoming `z`. |
| **`0`** | **`0`** | **Yes** | Exact match. |
| **`1`** | **`1`** | **Yes** | Exact match. |
| **`x` or `z`** | **`0` or `1`** | **No** | Incoming unknowns do not become wildcards; they fail to match literal branch values. |

---

### 3. `casex` (`?`, `x`, and `z` as Wildcards Everywhere)
In `casex`, **`?`, `x`, and `z` act as wildcards on both sides**—whether written in the case statement branches or present in the incoming data.

| Incoming Data | Case Branch Value | Does it Match? | Why? |
| :--- | :--- | :--- | :--- |
| **`0` or `1`** | **`?` (or `z`)** | **Yes** | The `?`/`z` in the branch acts as a wildcard, matching incoming `0` or `1`. |
| **`x` or `z`** | **`0` or `1`** | **Yes** | **The Hazard:** An incoming `x`/`z` acts as a wildcard, matching literal `0` or `1` branch values. |
| **`?`** | **`0` or `1`** | **Yes** | An incoming `?` acts as a wildcard, matching literal `0` or `1` branch values. |
| **`?`** | **`?` (or `x`/`z`)** | **Yes** | Both sides contain wildcards, resulting in a match. |
| **`0`** | **`0`** | **Yes** | Exact match. |
| **`1`** | **`1`** | **Yes** | Exact match. |
